# Tenant Communication Standards

## 1. Required elements of every reply

Every tenant-facing reply must include: an acknowledgement that the ticket was received, the category and
priority assigned, the applicable response and resolution window per the SLA Response & Resolution Times
document, and the ticket reference number.

## 2. Tone guidelines

Replies should use plain language, avoid internal jargon or trade abbreviations, and acknowledge any
inconvenience without being overly formal. A tenant should never need to ask "what does that mean?" after reading
a reply.

## 3. Update cadence

Emergency tickets receive a tenant update at least once every hour until resolved. Urgent tickets receive a daily
update while open. Routine tickets receive an update only when the status actually changes (dispatched, in
progress, resolved) — daily updates on Routine tickets with no change are not required and add noise.

## 4. Prohibited language

Do not promise a specific vendor arrival time that the vendor has not itself confirmed. Do not state or imply
fault (tenant or landlord) before a technician has actually assessed the issue on-site — a drafted reply that
assigns blame ahead of assessment must be corrected before it is sent.

## 5. Language and accessibility

Replies should default to the tenant's language of first contact where the helpdesk system supports it, and use
short sentences and paragraph breaks so the message is easy to read on a phone screen.
